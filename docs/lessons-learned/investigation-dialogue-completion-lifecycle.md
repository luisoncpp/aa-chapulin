# Investigation Dialogue Completion & Navigation Lifecycle

## Context & Problem
During crime scene exploration, examining an environment hotspot triggers narrative dialogue that awards evidence, introduces critical testimony clues, or triggers progress flags.

If the main investigation navigation (`#investigation-controls`: "🔍 Examinar", "💬 Hablar", "🏃 Moverse", "⚖️ Ir a Juicio") is revealed immediately upon clicking a hotspot, the player can click "Hablar" or "Examinar" mid-dialogue. Because the dialogue queue is FIFO and single-channel, opening a new menu topic overwrites the active queue and discards the uncompleted `onComplete` callback, preventing evidence grants and progression flags from ever firing.

Furthermore, exiting examine mode immediately after every single hotspot click created friction by forcing the player to click "Examinar" again after every clue inspected.

## What Was Learned
1. **Completion-Gated Navigation Locking**: During active hotspot investigation dialogue, navigation controls must remain hidden and secondary menu triggers (`openTalkMenu`, `startExamineMode`, `openMoveMenu`) must be blocked until the dialogue queue exhausts and the `onComplete` callback marks the hotspot examined.
2. **Examine Mode Persistence**: When a hotspot inspection dialogue completes, the game remains in examine mode (`startExamineMode()`), restoring the hotspot click layer, examine-mode shrunk prompt plate, and "Volver" button. This allows fluidly inspecting multiple scene clues in sequence. Exiting back to the general investigation menu happens only when the player explicitly clicks "Volver".
3. **Canonical Completion Hook**: Marking a hotspot examined must occur inside the `onComplete` callback of the dialogue queue, not on the initial click. This guarantees that all lines, clue grants, and SFX have been experienced before the game state recognizes the inspection as completed.
4. **Dialogue Presentation Isolation**: During hotspot dialogue playback, the `.examine-mode` class is temporarily stripped from the dialogue box and game screen, and `.visible-hotspots` is removed from the container. This ensures dialogue lines render with normal 120px height, full-sized font, advance arrow, and character staging without hotspot hover conflicts.
5. **Talk Dialogue Navigation Locking**: Selecting a talk topic hides `#investigation-controls` and sets `isFirstTimeDialogue = true` for the same reason hotspot dialogue does: the side buttons must not float over the conversation, and `openTalkMenu`/`startExamineMode`/`openMoveMenu` must stay blocked so the topic's `onComplete` (unlock notification, progress check, menu reopen) is never discarded. Both are reset in `onComplete`, before the talk modal reopens (the guard would otherwise swallow the reopen).
6. **Talk Menu Reopening Persistence**: Similar to examine mode persistence, completing a conversation topic dialogue automatically reopens the talk options modal (`openTalkMenu()`) with newly unlocked topics, removing the friction of having to click "Hablar" repeatedly for each topic while allowing the user to dismiss the menu with the `X` button.
7. **Scene Intro Navigation Locking**: When entering a location that triggers an introductory dialogue (initial entrance or conditional event re-visit), `#investigation-controls` must be hidden with `.hidden` and `isFirstTimeDialogue` set to `true`. This prevents the side navigation buttons from floating over opening exposition and avoids race conditions where clicking "Examinar" or "Hablar" mid-intro would cancel the completion callback that marks the intro played and restores resident character staging. Once the intro dialogue completes, `.hidden` is removed, `isFirstTimeDialogue` resets to `false`, and `restoreSceneIdlePose()` restores the character sprite.
